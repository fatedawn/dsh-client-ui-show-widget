# show_widget 对照实验：同数据，两条路径

目的：用同一份数据、同一句提示词，分别走「旧模式」和「新模式」，把结果并排看。

## 共用数据

工具清单（下称 DATASET）：

| 工具 | 用途 | 状态 |
| --- | --- | --- |
| read_file | 读取文件 | 可用 |
| write_file | 写入文件 | 可用 |
| bash | 执行命令 | 可用 |
| todo_write | 维护待办 | 可用 |
| show_widget | 渲染小组件 | 新增 |

---

## A 臂：旧模式（纯 Markdown）

提示词：

```
用一张表格列出这些工具及其用途和状态：read_file(读取文件/可用)、
write_file(写入文件/可用)、bash(执行命令/可用)、todo_write(维护待办/可用)、
show_widget(渲染小组件/新增)。只输出表格，不要别的话。
```

预期：直接出 GFM 表格，无卡片、无沙箱。

---

## B 臂：新模式（show_widget）

提示词：

```
用 show_widget 画一张表格，列出这些工具及其用途和状态：
read_file(读取文件/可用)、write_file(写入文件/可用)、bash(执行命令/可用)、
todo_write(维护待办/可用)、show_widget(渲染小组件/新增)。
标题叫「工具清单」。只调用一次，不要输出 Markdown 表格。
```

预期：出现标题为「工具清单」的卡片，卡内是 HTML 表格。

---

## C 臂：旧模式的"交付"路径（磁盘文件）

提示词：

```
把这张工具表格写成一个 HTML 文件放到项目根目录，用 present 交付给我。
```

预期：文件卡片，需要点开或者下载才能看到内容。

---

## 对照维度

| 维度 | A 旧-Markdown | B 新-widget | C 旧-交付文件 |
| --- | --- | --- | --- |
| 要不要落盘 | 不用 | 不用 | 要 |
| 内容在哪看 | 消息流内 | 消息流内 | 卡片 + 打开文件 |
| 能否跑脚本 | 否 | 是（allow-scripts） | 是（浏览器打开后） |
| 样式可控 | 弱 | 强（自带 CSS/SVG） | 强 |
| 高度自适应 | 天然 | 需上报（20–2000px） | 不适用 |
| 模型回执 | 表格文本进上下文 | 一行文字 | 文件路径进上下文 |

---

## 判读要点

- A 与 B 的差异在**渲染载体**，不在数据本身；两边数据必须一致才算公平。
- B 的表格如果套在卡片里但样式塌了，问题在 CSS 或高度上报，不在数据。
- C 的价值在于留档；B 的价值在于即读即看，不留文件。
